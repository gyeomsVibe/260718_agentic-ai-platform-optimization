## 3. 실행 구조와 올바른 순서

```text
기준 이미지·캐릭터 계약 고정
  → 기본 동작 9행 생성·추출
  → 구조 검사 + 인접 프레임 변화 검사
  → 4개 기본 방향 → 16방향 확장
  → 최종 시트 단 1회 조립
  → 접촉 시트·GIF·잔색·규격 검수
  → 설치 전 백업·해시 비교
  → 설치 후 Codex 표시 확인
```

### 핵심 운영 원칙

1. 기준 이미지, 파일명, 의상 계약을 시작 전에 고정한다.
2. 오류가 난 경우 한 프레임만 다른 생성본으로 섞지 않는다. 해당 **행 전체**를
   같은 기준으로 고친다.
3. 프레임이 바뀌면 최종 스프라이트·접촉 시트·GIF·검사 결과를 한 묶음으로 재생성한다.
4. 숫자로 판단할 수 있는 규격·알파·빈 칸·기준선 문제는 자동 검사로 먼저 좁힌다.
5. 얼굴·옷·방향·테두리 품질은 실제 이미지로 최종 확인한다.
6. 독립적인 읽기·검사는 묶어서 실행하고, 같은 원인의 실패가 3회 반복되면
   문구만 바꿔 재시도하지 말고 원인을 재분석한다.

## 5. Codex 로컬 이미지 뷰어 샌드박스 장애 사건

### 5.1 증상

Codex의 로컬 이미지 뷰어가 후보 시트와 GIF를 열 때 다음 오류로 실패했다.

```text
fs sandbox helper failed with status exit code: 1:
windows sandbox failed: helper_unknown_error: setup refresh had errors
```

그 결과 사람 눈으로 해야 하는 동기화, 바지 색, 크기, 붉은·초록 테두리 검수가
중단되었다. 이는 Pet 이미지 생성 품질의 오류가 아니라 **검수 도구의 실행 환경 오류**다.

### 5.2 증거와 원인 판정

샌드박스 로그에 다음 실패가 기록되었다.

```text
write ACE grant failed on C:\tmp: SetNamedSecurityInfoW failed: 5 (Access denied)
setup refresh: ... errors=["write ACE failed on C:\\tmp: SetNamedSecurityInfoW failed: 5"]
```

확인된 사실:

- 문제 작업공간을 대상으로 실행될 때 writable root에 `C:\tmp`가 포함됐다.
- 해당 `C:\tmp`에서 Codex 샌드박스 설정 과정이 `CodexSandboxUsers` 권한을
  부여하려 했으나 Access Denied로 실패했다.
- 샌드박스 사용자·그룹 자체는 존재·활성 상태였다.
- `C:\tmp` 소유자는 `BUILTIN\Administrators`였고, 사용자 컨텍스트가 ACL을
  수정할 충분한 권한을 받지 못한 상태였다.

확정하지 않은 사항:

- `C:\tmp`가 어떤 프로그램 또는 어떤 승격 과정에서 생성됐는지는 증거로 확정되지
  않았다. “관리자 권한으로 생성됐다”는 표현은 추정이므로 사건 기록에서 사용하지 않는다.
- Codex 앱 제품 자체의 결함이나 이미지 파일 형식 결함은 직접 원인으로 확인되지 않았다.

### 5.3 선행 조치와 효과 판정

- 공식 Microsoft Store `repair`가 1회 실행됐다.
- 이후에도 이미지 뷰어 오류가 남아 있었다.
- 따라서 Store Repair가 이 문제를 해결했다는 근거는 없으며, 관측상 효과는
  확인되지 않았다.

### 5.4 직접 수정

`C:\tmp`에 대해 승격된 `icacls` 1회를 실행해 다음 권한을 부여했다.

- 현재 사용자 `Kimyoongyeom`: Full Control, 하위 항목 상속
- `CodexSandboxUsers`: Modify, 하위 항목 상속

수정 중 파일 삭제, 앱 강제 종료, 샌드박스 계정 삭제·재생성, 레지스트리 변경,
방화벽 변경, Reset, 재설치는 수행하지 않았다.

### 5.5 직접 검증 결과

동일한 작업공간과 writable root 조건에서 다음 성공 로그가 확인됐다.

```text
cwd=D:\D_Workspace_NB\-agentic-ai-workspace\-antigravity-workspace\260713_pc-optimization
payload_len=16472
granting write ACE to C:\tmp for sandbox group and capability SID
setup refresh: processed 3 write roots (read roots delegated); errors=[]
```

또한 다음 이미지가 실제로 열렸다.

```text
D:\D_Workspace_NB\-agentic-ai-workspace\-antigravity-workspace\260713_pc-optimization\qa-contact-sheet-current.png
```

판정: **수정 완료 (VERIFIED_RESULT)**.

### 5.6 금지된 롤백과 재발 방지

아래 명령은 현재 정상 상태를 제거하고 같은 오류를 다시 만들 수 있으므로 실행하지 않는다.

```powershell
icacls C:\tmp /remove "Kimyoongyeom" "CodexSandboxUsers"
```

새 writable root를 Codex에 추가할 때는 다음을 먼저 점검한다.

1. 해당 폴더에서 `CodexSandboxUsers`가 Modify ACE를 받을 수 있는가
2. 현재 실행 컨텍스트가 필요한 ACL 변경 권한을 갖는가
3. 설정 후 동일 workspace에서 `setup refresh`가 `errors=[]`인지
4. 실제 이미지 하나를 열어 사용자 체감 결과까지 확인했는가

## 6. 남은 품질 검수·수정 계획

이미지 뷰어 장애는 닫힌 사건이다. 이후에는 다음 순서만 수행한다.

1. 설치본과 후보 시트의 해시를 비교해 최신 파일을 검수 대상으로 확정한다.
2. 접촉 시트·GIF를 열어 행별 크기·발 기준선·의상·바지 색·방향·잔색을 확인한다.
3. 규격 문제만 있으면 자동 정규화/단일 잔색 보정 후보를 만든다.
4. 정체성 문제(얼굴·옷·바지·포즈)가 있으면 그 **행만** 기준 계약으로 재생성한다.
5. 수정한 경우에는 최종 아틀라스·접촉 시트·GIF·구조 검사·해시를 한 묶음으로 갱신한다.
6. Codex Pet 선택기에서 최신 설치본이 표시되는지 확인한다.

중단 조건:

- 같은 도구 오류가 3회 반복되면 재생성·재시도 루프를 멈추고 로그, 원인, 최소 수정안을
  먼저 기록한다.
- 이미지 뷰어가 다시 실패하면 Pet 품질을 의심하지 말고, 먼저 writable root ACL과
  `setup refresh` 로그를 확인한다.

  쓰지 말고, “로그로 Access Denied가 확인된 경우의 진단 절차”로만 기록한다.
- Store Repair를 만능 해결책으로 표현하지 않는다. 이 사건에서는 선행됐으나 효과가
  확인되지 않았다.
