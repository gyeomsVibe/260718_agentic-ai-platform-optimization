# Gyeom Companion 생활 모션 전수검수 보고서

## 판정

**생활 모션 MVP: 통과**

이전 버전은 9개 상태 중 7개가 기존 이미지와 같고, 자동 행동 사이의 정적 구간이
길어 상품성 판정이 취소됐다. 이번 버전은 대기 상태를 하나의 반복 행으로 처리하지
않고, 생활 동작 4묶음과 기존 교감·업무 상태를 다중 클립 재생기로 연결했다.

다만 이 판정은 Companion 생활 모션 MVP에 대한 것이다. Codex 내부 작업 상태를
자동으로 읽는 기능이나 고객별 추가 캐릭터 제작까지 완성됐다는 뜻은 아니다.

## 새로 구현한 생활 동작

| 동작 | 프레임 | 화면 의미 |
| --- | ---: | --- |
| 호흡·눈깜빡임 | 8 | 대기 중에도 살아 있는 미세 움직임 유지 |
| 하품 | 6 | 졸림과 시간 경과를 읽을 수 있는 큰 생활 동작 |
| 기지개 | 8 | 양팔을 올리고 다시 기본 자세로 돌아오는 큰 실루엣 변화 |
| 두리번거리기 | 8 | 좌우 시선과 고개 기울임으로 주변을 살피는 행동 |

생활 모션은 `192×256` 셀을 사용한다. 기존 `192×208` 셀보다 위쪽 투명 공간을
48픽셀 더 확보해, 기지개에서 손이 올라가도 몸을 작게 축소하지 않았다. 창의 아래쪽
기준을 고정하므로 상태가 바뀌어도 발 위치가 유지된다.

## 크기·비율 검사

- 기존 정본 몸 높이: `202px`
- 호흡·눈깜빡임: 모든 프레임 `202px`
- 하품: `202~210px`
- 기지개: `202~240px` — 몸 크기는 유지되고 올라간 팔 때문에 전체 높이만 증가
- 두리번거리기: `200~202px`
- 생활 모션 발 기준선: `251px`
- 셀 가장자리 접촉 프레임: `0`
- 사용하지 않는 셀의 불투명 픽셀: `0`
- 사용 프레임: `30`

## 실제 화면 60초 관찰

시험본은 기존 설치를 종료하거나 교체하지 않고 가로 위치를 320픽셀 옮겨 실행했다.
0.5초 간격으로 114장을 수집했으며 실제 관찰 구간은 `58.601초`다.

| 상태 | 화면에서 관찰된 캡처 수 |
| --- | ---: |
| 호흡·눈깜빡임 | 90 |
| 두리번거리기 | 5 |
| 기지개 | 4 |
| 하품 | 4 |
| 손 흔들기 | 5 |
| 검토 | 6 |

필수 6상태가 모두 나타났고, 생활 동작이 끝날 때마다 호흡·눈깜빡임으로 복귀했다.
크기가 작아지는 전환이나 발 기준선 점프는 최종 접촉표에서 발견되지 않았다.

## A/B 판정

- A안: 기존 안정화본은 대기 화면의 변화 폭이 작고 큰 생활 동작이 없었다.
- B안: 4초부터 두리번거리기가 시작되고, 약 11초 기지개, 20초 하품,
  32초 손 흔들기, 46초 검토가 나타났다.
- 결론: B안은 60초 안에 사용자가 구별할 수 있는 큰 동작과 미세 동작을 함께
  보여 주므로 이전 버전보다 명백하게 풍부하다.

화면 증거는 `life-motion-runtime-contact-sheet.png`와
`life-motion-ab-contact-sheet.png`에 보존했다.

독립 시각 검수자도 동일 캐릭터·의상·전신·발 기준선이 안정적이고 네 생활 동작이
읽히며, B안이 A안보다 명확히 풍부하다고 판정했다. 수정 요구는 없었다. 판정 원문은
`life-motion-independent-visual-qa.json`에 보존했다.

## 실행 중 발견하고 교정한 문제

1. 첫 하품·두리번거리기 생성본이 상반신만 나와 전신 조건으로 기각하고 재생성했다.
2. 이미지 생성 서버가 호흡 행 요청에서 HTTP 500을 두 번 반환해 독립 생성 작업으로
   전환했다.
3. 첫 60초 감사에서 Windows PowerShell 문자 인코딩 때문에 상태명 정규식이 실패했다.
4. 다음 감사에서는 창 자동 종료와 마지막 캡처가 충돌하는 종료 경쟁 조건이 발생했다.
5. 접촉표 선택 인덱스의 PowerShell 배열 연산 오류를 교정했다.
6. 기존 실행 중인 펫과 시험본이 같은 위치에 겹친 것을 발견해 시험본에만 위치
   오프셋을 적용했다.

위 실패들은 성공으로 계산하지 않았다. 보존된 실제 캡처를 별도 요약기로 재검증했고,
최종 상품 자동 감사 `life-motion-product-audit.json`은 오류 없이 `ok: true`를 반환했다.

## 남은 상품 경계

- `running`, `waiting`, `review`, `failed` 등 업무 상태는 외부 상태 명령과 우클릭
  메뉴로 사용할 수 있다.
- Codex 작업 내용을 자동으로 읽어 상태를 바꾸지는 않는다.
- 고객용 상품으로 판매할 때는 캐릭터 사용권과 고객별 모션 범위를 별도 계약해야 한다.

## 최종 결론

이 버전은 “기존 모션을 느리게 재생한 안정화본”이 아니라, 서로 다른 생활 행동을
실제 화면에서 주기적으로 보여 주는 Companion 생활 모션 MVP다. 기술 안정성,
크기·비율, 생활감, 실제 화면 출현 조건을 모두 통과했으므로 **MVP 출시 Go**로
판정한다.
