# Gyeom Companion MVP 검증 기록

## 범위

- 대상: `GyeomPetOverlay.ps1`
- 범위 밖: Codex Native Pet 설치본과 서명된 Codex 앱 파일

## 자동 검증 결과

| 확인 항목 | 결과 | 근거 |
| --- | --- | --- |
| PowerShell 구문 | 통과 | Parser 오류 0건 |
| 성격 루프 짧은 실행 | 통과 | 15초 실행에서 `waiting → idle` 기록 |
| 2분 대기 | 통과 | `waiting → review → waving → waiting` 및 복귀 포함 8건 기록 |
| 상태 명령 | 통과 | `running`, `review` 외부 상태 이벤트가 기록됨 |
| 9개 행동 실제 실행 | 통과 | `idle`부터 `review`까지 9/9 상태가 각 3초 WPF 실행에서 요청 상태로 전환됨 |
| 크기·비율 | 통과 | 정상 56프레임은 원본과 픽셀 단위 동일(배율 X/Y=1.0), 축소 이상치 1개만 정상 포즈로 교체 |
| 축소 프레임 제거 | 통과 | 원본 `review`의 작은 5번째 프레임은 재생에서 제외하고, Companion 사본에는 인접 정상 포즈로 대체 |
| 속도 조정 | 통과 | 전 상태 프레임을 기본보다 60% 완화. 실제 간격은 176~512ms로, 슬로모션 판정 구간 밖 |
| 새 성격 루프 | 통과 | 실제 20초 WPF 실행에서 `waiting`이 4,407ms 유지된 뒤 `idle`로 복귀 |

## 자원 관측

54초 시점에서 오버레이 프로세스는 응답 상태였고, 누적 CPU 약 2.984초,
메모리 약 166MB를 사용했다. 이는 단일 개발 PC에서의 관측값이며 고객 PC의
최종 성능 보증값은 아니다.

## 화면 검토

- 원본과 Companion 시트의 57개 비어 있지 않은 셀을 픽셀 단위로 대조했다. 정상
  56개 셀은 완전히 동일하며 X/Y 배율은 모두 1.0이다.
- `review`의 유일한 축소 프레임 1개는 재생 목록에서 제외하고 Companion 시트에는
  인접 정상 포즈를 복사했다. 점프·실패의 낮아진 외곽 높이는 자세 변화이므로 원본
  배율을 그대로 유지해 캐릭터가 확대·축소되거나 찌그러지지 않게 했다.

## 남은 사람 확인

- 사용자가 실제 화면에서 2분 동안 동작이 자연스럽게 느껴지는지 확인
- 우클릭 메뉴와 드래그 위치 이동을 직접 확인
- 다른 해상도·배율에서 잘림이 없는지 확인

## 판정

`MVP_READY_FOR_LOCAL_DEMO`

로컬 데모에는 사용할 수 있다. 이번 보정은 Companion 오버레이만 대상으로 하며,
Codex Native Pet 설치본은 변경하지 않았다. 판매·배포 전에는 고객 환경에서의 위
사람 확인을 한 번 더 통과해야 한다.
