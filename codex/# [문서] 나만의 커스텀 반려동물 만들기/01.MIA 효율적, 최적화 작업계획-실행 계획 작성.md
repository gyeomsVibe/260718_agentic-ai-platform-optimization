# MIA 효율적, 최적화 작업계획-실행 계획 작성 모드 발동

윤겸스 판단에 동의합니다. 지금은 **처음부터 다시 만드는 것보다, 기존 10개 완료분을 자산으로 고정하고 남은 3개와 최종 조립을 최적화하는 편이 맞습니다.**

다만 `10/13 완료`는 “최종 완성도 77%”와 같지는 않습니다. 현재는 프레임 작업은 상당히 진행됐지만, 최종 스프라이트·GIF·시각 검수 결과가 이전 프레임 기준이라 **마지막 조립 단계가 최신 상태를 따라가지 못한 상태**입니다.

## 전수 진단 결과

| 과잉 소모 원인 | 확인 근거 | 해결 원칙 |
|---|---|---|
| 프레임 수정 뒤 최종 산출물을 다시 만들지 않음 | 현재 프레임은 최신, 스프라이트·검수 파일은 이전 시점 | 프레임 변경 시 조립·검수 산출물을 자동으로 무효화 |
| 검수가 작업 후반에 집중됨 | 9개 행은 구조 검증 통과했지만 모두 “재생 중 잘림·안정성 확인 필요” 경고 | 각 행 완료 직후 짧은 재생 검수를 통과해야 다음 단계 진행 |
| 이미지 조립 환경 준비가 늦음 | Pillow 부재로 최종 합성 직전 중단 | 생성 전에 실행 환경·필수 라이브러리·조립 명령을 먼저 검증 |
| 방향 전환의 난도 | 좌·우 달리기는 일반 생성 대신 구성요소 추출·재조합·안정본 보관 절차가 필요했음 | 방향별 외형은 한 장의 기준 시트로 확정한 뒤 파생 작업 |
| 참조 파일명 변경으로 관리 정보가 흔들림 | 실제 이미지 캐시는 모두 동일하지만 요청 파일 체크섬은 변경 | 원본 이미지와 작업 캐시를 분리하고, 경로 변경은 메타데이터 갱신으로만 처리 |
| 완료 정의가 섞여 있음 | 행 작업은 완료지만 최종 설치·독립 시각 검수는 미완료 | `프레임 완료 → 조립 완료 → 시각 검수 완료 → 설치 가능`의 4단계로 분리 |

핵심 구현 난제는 “이미지 생성” 자체보다 **일관된 캐릭터를 여러 동작·방향·프레임에 유지하면서, 수정된 프레임이 최종 산출물에 정확히 반영되도록 만드는 공정**입니다. 이 연결이 느슨하면, 이미 만든 결과를 다시 검수하거나 재생성하는 시간이 폭증합니다.

## 최적화된 실행 계획

### 1. 기존 완료분을 동결 기준으로 확정

- 7개 원본 이미지와 합본 이미지를 기준 참조로 고정합니다.
- 현재 보존된 프레임 74개와 좌·우 안정본은 유지합니다.
- 기존 10개 작업을 재생성하지 않습니다.
- 프레임·조립본·검수본의 버전 연결표를 하나로 관리합니다.

### 2. 최종 조립 경로를 먼저 복구

이미지 생성 없이 다음 순서로 진행합니다.

1. 이미지 조립 환경을 먼저 검증
2. 현재 프레임으로 스프라이트 시트 재구성
3. 연락처 시트와 동작별 GIF 생성
4. 독립 시각 검수
5. 통과한 행만 “최종 조립 가능”으로 승격

이 단계가 통과해야 기존 10개 완료분이 실제 완성 자산이 됩니다. 실패하면 전체를 다시 하지 않고, **실패한 행·프레임만** 고칩니다.

### 3. 남은 3개는 생성 횟수를 최소화

- `look-cardinals`: 정면·후면·좌·우 방향을 각각 따로 만들지 않고, **하나의 4방향 기준 시트**로 확정
- `look-row-9`, `look-row-10`: 확정된 방향 기준 시트와 기존 캐릭터 규격을 사용해 파생
- 각 작업은 `기준 시트 → 프레임 추출 → 짧은 재생 검수 → 승인` 순서로 끝냅니다.
- 재시도는 “한 문제-한 원인-최소 수정”만 허용하고, 캐릭터 전체 재생성으로 돌아가지 않습니다.

## 재개 판단

**권장: 원래 작업을 계속하되, 순서를 바꿉니다.**

먼저 기존 10개를 최신 프레임 기준으로 조립·검수하여 기반을 확정하고, 그 다음 남은 3개를 진행합니다. 이것이 현재까지의 작업을 보존하면서 16시간 이상 걸린 재작업 구조를 끊는 가장 효율적인 경로입니다.

이번 분석 단계에서는 파일을 수정하거나 이미지 생성을 재개하지 않았습니다.
