# 글로벌 룰 변경 이력

## v5.22.0

- 사용자 지시(2026-09-22): 사용자가 올라마가 일한 것을 알아보도록 보고 줄과 MCP 도구 결과 앞에 `[올라마]`를 붙인다.

## v5.21.0

- 근본 원인(2026-09-22): 에이전트는 도구 목록 안에서 고른다. 셸 명령 `olla`는 목록에 없어 Read·Grep과 경쟁하지 못했다(Biz항해 세션: 안내 11회에도 0회). 도구 선택은 요청과 도구 이름·설명의 의미 일치가 가장 강한 예측 변수(BiasBusters arXiv:2510.00307), 설명 문구만 바꿔도 선택이 크게 바뀜(arXiv:2505.18135). 올라마를 MCP 도구(`local_read_map`·`local_draft`·`local_search`)로 3대 도구 모두에 등록하고 규칙을 그 이름으로 바꿨다(조항은 더 짧아짐).

## v5.20.0

- 사용자 지시(2026-09-22): 3대 도구끼리의 통신(릴레이·브리핑·스트림·로컬 지시)은 영어, 사용자 보고만 한국어. Biz항해 세션에서 작업 위치가 260자를 넘어 셸과 Stop 훅이 `ENOENT uv_spawn bash.exe`로 실패해 보고 길이 제한이 작동하지 않았으므로, 셸은 프로젝트 루트에 두고 절대 경로를 쓴다.

## v5.19.0

- 사용자 지시(2026-09-22): 도구와 로컬 모델 사이 작업 대화는 한국어일 필요가 없다. 로컬 모델은 영어 지시를 더 잘 따르므로 영어로 시키고, 사용자에게 보일 글일 때만 `--ko`. 읽기 훅은 캐시된 요약본을 그 자리에서 건네고, 없으면 뒤에서 만들어 둔다(Biz항해 세션: 알림만으로는 사용 0건).

## v5.18.0

- 사용자 지시(2026-09-22): 사용자에게 주는 명령은 실행 환경에 맞춘다. bash 문법(`ALLOW_PUSH=1 git push`)을 PowerShell 앱 터미널에서 실행해 푸시가 실패한 사례.

## v5.17.0

- 사용자 지시(2026-09-22): 한눈에 과정이 보이는 보고. 결론 → 과정(A → B → C) → 근거 → 남은 일. 근거: NN/g 시선 추적(사용자는 단어의 20~28%만 읽고 첫 줄과 줄 앞머리를 훑음, F-패턴·역피라미드), 사용자 1만 명 연구(간결·근거 제시 응답 선호, arXiv:2508.04713), LLM은 간결하라 해도 약 50% 부풀림(Verbosity Compensation, arXiv:2411.07858) → "손실 없이 줄일 수 있는 말은 지운다". 소통 절을 3항으로 합쳐 글자 수를 줄였다.

## v5.16.0

- 사용자 지적(2026-09-22): 3줄 이내여도 한 줄에 여러 사실·괄호를 몰아넣어 읽기 힘들었다. 보고 모양을 고정: 굵은 결론 한 줄 + 사실 하나씩 한 줄 글머리 최대 3개 + 필요 시 남은 일. 굵은 첫 줄만 읽어도 전체를 알게 한다. 3대 도구 공통.

## v5.15.0

- 사용자 지적(2026-09-22): "결과 1~3줄" 규칙이 있는데도 번호 절·중첩 목록·코드 블록·단계별 진행 설명으로 길게 보고했다. 형식 금지를 명시하고, 길면 내용이 맞아도 위반으로 정했다. 3대 도구 공통.

## v5.14.0

- 사용자 지적(2026-09-22): 로컬 모델을 규칙으로만 두니 도구가 계획 단계에서 빠뜨렸고, 로컬 지시도 모호했다(영어 지시 속 "in Korean" 한 마디 → 영어 답). 작업 시작 전 로컬 분업을 스스로 정하고, 로컬 지시에는 언어·형식·길이·예시를 적게 했다. 실측: 한국어 규칙+예시를 주면 3/3 한국어, `olla ask --ko`(한국어 규칙·검사·1회 재시도)는 3/3 첫 시도 통과. 장치: `olla hook-plan`(작업 시작 시 분업 한 줄), Codex는 `~/.codex/hooks.json` UserPromptSubmit에 등록.

## v5.13.0

- 사용자 지시(2026-09-22): 출력은 사용자가 볼 핵심 요약만, 한국어로 쓰고 전문 용어는 영어를 괄호로 병기한다(예: 캐시(cache)). 기존 "결과 1~3줄" 조항에 병기 규칙만 더했다.

## v5.12.0

- 사용자 지시(2026-09-21): 로컬 모델은 토큰이 0이다. 세 도구가 지시 없이 스스로 예상 토큰을 추정해 로컬을 부려 쓴다. 가장 큰 절감은 "비싼 모델이 읽기 전에 로컬이 먼저 읽고 줄이는 것"이므로 약 3,000토큰 넘는 읽기는 `olla digest` 요약본을 먼저 거친다(LLMLingua, EMNLP 2023: 작은 모델로 입력 최대 20배 압축). 실측: 753줄 파일 10,464토큰 → 요약본 855토큰(−91.8%), 핵심 위치는 맞췄으나 보조 경로 하나를 놓쳐 "요약본은 지도, 줄은 직접 확인"을 규칙에 넣었다. `olla route`가 비용을 추정해 경로를 고른다.

## v5.11.0

- 사용자 지시(2026-09-21): 세 도구가 파일럿 밖, 어느 프로젝트에서든 로컬 모델을 부려 쓰게 했다. 공용 명령 `olla`(ask/edit/find)를 PATH에 두고, 기계적인 일은 자기 한도보다 로컬을 먼저 쓰고 판단이 필요하거나 검사에 실패할 때만 스스로 올라가는 캐스케이드를 공통 규칙으로 고정했다. 근거: FrugalGPT(arXiv:2305.05176), RouteLLM(ICLR 2025), GitHub Ollama 위임 도구들의 공통 분업. 로컬 결과의 판정은 여전히 호출한 도구가 한다.

## v5.10.0

- 사용자 지정(2026-09-21): Claude Code는 Codex와 동등한 부지휘자다. Codex 활동 중에는 Codex의 지시를 받고, 부재 중(한도·정지·무응답)에는 모든 권한을 대행한다. Codex는 복귀 시 부재 중 승인된 것을 먼저 재검토한다. v5.9.0에서 Claude를 검증자로만 둔 정의를 대체한다.

## v5.9.0

- 역할별 규칙을 외부 근거에 맞춰 보강했다(`REFERENCES.md`). 역할 구조는 Anthropic의 orchestrator-workers·evaluator-optimizer, 실패 대응은 MAST(NeurIPS 2025, 14개 실패 유형), 검증자 분리는 LLM 판정자의 자기 선호 편향 연구를 따른다.
- Codex(지휘자): 위임마다 목표·허용 파일·합격 명령·종료 조건, 구체화 못 하면 위임 보류(FM-1.1·FM-2.2). 배정 전 중복 확인(FM-1.3 단계 반복, 최다 실패). 작성자가 유일한 검증자가 되지 않게(FM-3.3·자기 선호 편향).
- Antigravity(작업자): 빠진 정보는 추측 대신 돌려줌(FM-2.2). 실패·부분 완료 보고와 변경 파일 목록 일치(FM-2.4·FM-2.6).
- Claude Code(검증자)의 역할 정의는 `~/.claude/CLAUDE.md`에 둔다(이 생성기의 배포 대상이 아님).
