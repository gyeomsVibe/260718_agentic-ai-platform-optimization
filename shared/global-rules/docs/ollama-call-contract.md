# Ollama 호출 계약: 미숙한 계산기 출력의 격리와 검증

Ollama는 스스로 규칙을 읽고 책임지는 에이전트가 아니다. Codex·Claude·Antigravity가 이 계약을 **작업마다 문서로 발행하고 내용 자체를 호출에 넣는다.** 도구 등록이나 파일 경로만 전달하는 것은 계약 전달이 아니다.

## 호출 전: 꼭 필요한가?

1. 정확한 검색·추출·치환은 `rg`, 파서, 해시 비교, 테스트처럼 결정적 방법으로 끝낼 수 있는지 확인한다. 그렇다면 Ollama를 호출하지 않는다.
2. 모델이 필요하다면 한 호출의 일을 한 가지 기계 연산으로 제한한다. 모호한 설계, 승인, 성공 판정은 맡기지 않는다.
3. 아래 계약의 빈칸을 채워 파일로 남긴다. 자료의 해시는 호출 직전 원본에서 계산하고, 인수 조건은 결과를 보기 **전에** 고정한다.

## 작업 프로세스 매뉴얼 양식

```text
Work ID: <고유 ID>
Caller / independent judge: <호출자 / 별도 검증자 또는 독립 검사 명령>
Operation: <추출·분류·정확한 치환 중 하나>
Inputs: <필요한 최소 파일·행과 SHA-256 해시>
Allowed output and files: <정확한 스키마·최대 길이·수정 허용 경로>
Forbidden: <설계·승인·자가 채점·비밀 접근·범위 외 수정>
Bounds: <호출 1회 제한 시간·토큰/비용 상한>
Acceptance: <호출 전 고정한 원문 대조·스키마·해시·테스트 명령>
Stop: <실패 때 격리; 같은 원인 두 번째 실패 때 해당 경로 중단>
```

## 호출 후: 보류에서 합격으로

| 검사 | 실패하면 |
|---|---|
| 실제 출력이 있고 스키마·길이가 정확한가? | `exit 0`이어도 폐기한다. |
| 인용은 원본에 문자 그대로 있는가? 해시와 파일 경로가 허용 범위와 맞는가? | 없는 근거·다른 파일 결과를 폐기한다. |
| 고정 인수 테스트가 그대로이고 독립 실행해 통과하는가? 예상 변경 집합만 생겼는가? | 반영·공개를 막고 실패를 기록한다. |
| 사용한 로컬 토큰·벽시계·재작업을 기록했는가? | 비용 절감 주장을 `UNMEASURED`로 둔다. |

실패 결과는 별도 격리 영역에만 둔다. 동일 원인의 실패가 두 번이면 프롬프트를 무한히 고치거나 원격 유료 작업자로 자동 승격하지 않는다. 결정적 구현으로 좁히거나, 판단이 꼭 필요하고 승인 범위를 바꿔야 한다면 사용자에게 선택을 요청한다. 판단권과 최종 판정권은 Ollama에 없다.

## 현재 증거의 한계

UAOS U30의 로컬 파일럿은 `PROVIDER_ERROR`, 원격 재시도는 `TIMEOUT_PARTIAL`로 끝났다. 두 실행 모두 반영이 차단되어 런타임 게이트가 구현됐다는 주장은 할 수 없다. 이 문서는 **호출자 정책과 수동 검증 계약**이다. 자동화된 격리·검증은 별도 고정 테스트를 통과해야만 배포한다.
