# ai-env-maintenance — AI 환경 자동 유지보수

C 드라이브 여유를 목표선 위로 **자동 유지**하고, AI 데이터의 기본 위치를 D로 **수렴**시키는
주기 유지보수 도구. 3대 AI 도구(Claude Code·Codex·Antigravity) 합의체(C3P)가 `/CRITIC
/REDTEAM /OPTIMIZE`로 검토해 설계했다.

> **왜 여기(플랫폼 저장소)인가?** 정션 무결성·환경변수 계약·AI 캐시 유입 차단은 OS 하드웨어
> 튜닝이 아니라 **AI 플랫폼 라이프사이클 관리**다. 일반 디스크/전원/발열 튜닝은 260713에 있다.

## 무엇을 하나 (비유)

AI 도구들은 캐시·세션 기록을 계속 쌓는다. 우리는 그 큰 데이터를 D로 옮기고, 원래 자리에는
**정션(이정표)**을 남겨 뒀다. 이 도구는 **그 이정표가 멀쩡한지 주기적으로 순찰**하고,
찌꺼기를 치우고, 이정표가 풀렸으면 (안전할 때만) 다시 붙인다.

## 스크립트 3종

| 스크립트 | 성격 | 하는 일 |
|---|---|---|
| `Test-AiEnvHealth.ps1` | **읽기 전용** | 정션 계약·열거권한·설정 실효값·환경변수 12개·PATH·고아·용량 7축 판정 |
| `Repair-AiEnv.ps1` | 쓰기(기본 DRYRUN) | 일반 폴더로 되돌아간 정션을 **안전 게이트 통과 시에만** 재연결 |
| `Invoke-AiEnvMaintenance.ps1` | 오케스트레이터 | 위 둘을 묶어 주기 실행 + C/D 용량 감시 + 신규 유입 감시 + 경보 |

## 실행

```powershell
# 일간 감시 (변경 없음, 언제든 안전)
pwsh -File Invoke-AiEnvMaintenance.ps1 -Mode Watch

# 주간 정리 (Temp 정리 + 정션 복구 미리보기)
pwsh -File Invoke-AiEnvMaintenance.ps1 -Mode Weekly

# 정션 실제 복구까지 (앱 전부 종료 상태에서만; 안전 게이트가 재차 확인)
pwsh -File Invoke-AiEnvMaintenance.ps1 -Mode Weekly -RepairApply
```

종료코드 `0`=경보 없음, `1`=경보 있음(로그 확인). 로그: `%AI_HOME%\_maintenance-logs\`.

## 경로 규칙 (머신 고유값 없음)

- `$U = $env:USERPROFILE`, `$AiRoot = $env:AI_HOME`(미설정 시 `D:\AI-Models` 폴백).
- 스크립트에 사용자명·절대 사용자경로를 하드코딩하지 않는다. 다른 머신에서도 동작한다.
- `Test-AiEnvHealth.ps1` 상단 `$Contract` 표가 "어느 폴더가 어디로 연결돼야 하는지"의
  **유일한 기준**이다. 이관 대상을 바꾸면 이 표를 함께 갱신해야 검진이 의미를 가진다.

## 안전 게이트 (Repair-AiEnv.ps1) — C3P 합의 반영

| 게이트 | 방어 대상 |
|---|---|
| G1 프로세스 뮤텍스 | 앱 실행 중 정션 조작 → DB 손상/split-brain. 하나라도 켜져 있으면 전체 중단 |
| G2 열거 오류 0건 | ACL로 못 읽는 하위트리 → 거짓 부분집합 판정 |
| G3 내용·시각 검증 | C에만 있거나 C가 더 최신인 파일 → 자동 덮어쓰기 금지(병합위험 SKIP) |
| G4 2회 연속 확인 | 조회 실패의 거짓 음성(정션인데 아님으로 오판) |
| G5 삭제 금지 | 원본은 `.bak` 격리만. 실패 시 자동 재시도 없이 사용자에게 위임 |

## 스케줄 (예약 작업)

사용자 레벨 예약 작업 2개로 등록한다(관리자 불요).

| 작업 이름 | 트리거 | 인자 |
|---|---|---|
| `MIA_AiEnv_Watch` | 매일 | `-Mode Watch` |
| `MIA_AiEnv_Weekly` | 매주 | `-Mode Weekly` (복구는 DRYRUN, 실제 복구는 수동 `-RepairApply`) |

등록/해제는 `Register-AiEnvSchedule.ps1` 참조.

## 설계 배경 (합의 기록)

- 정션이 일반 폴더로 되돌아갔다 복구되는 **flapping** 이 실측으로 확인됨 → 주기 복구의 근거.
- 물리적 대이관은 사실상 종료(남은 큰 덩어리는 MSIX/ACL/rename-차단으로 이동 불가). 전략을
  **"이동"에서 "유입 차단 + 감시"로 전환**함. 환경변수 계약 12개가 신규 도구를 D로 유도한다.
- 목적함수 = **C 여유율을 목표선(40%) 위로 유지**(현재 48%대로 이미 충족). 유지 불가 시
  자동 조작이 아니라 경보.
