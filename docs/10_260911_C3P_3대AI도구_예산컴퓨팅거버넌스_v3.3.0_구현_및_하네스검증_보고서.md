## 1. 💡 ELI10 직관 요약 (모르는 걸 모르는 사용자를 위한 쉬운 설명)

### 왜 이 작업을 했나요?
AI 코딩 도구(Codex, Claude, Antigravity)를 사용할 때 가장 중요한 두 가지는 **"비용(토큰, Token)"**과 **"안전(Safety)"**입니다.
- 그동안 “토큰을 아끼자”는 규칙들이 여러 군데에 흩어져 있어서 한눈에 관리하기 어려웠습니다.
- 컴퓨터에서 무료로 돌릴 수 있는 경량 AI(Ollama 등)를 언제 쓰고 언제 쓰지 말아야 할지에 대한 기준이 없었습니다.
- 특히 Antigravity 도구는 규칙 파일이 **11,800자**를 넘으면 작동하지 않는데, 여유 공간이 거의 없었습니다.

### 무엇을 해결했나요?
1. **규칙 한곳으로 모으기 (Consolidation)**: 파편화되어 있던 예산 절감 규칙을 Token and compute budget governance (토큰 및 컴퓨팅 예산 거버넌스)라는 단 하나의 장으로 완벽히 통합했습니다.
2. **무료 로컬 AI의 안전 울타리 설치**: 무료 로컬 모델(Ollama)은 단순하고 안전한 작업에만 쓰고, 중요한 비밀번호, 서버 배포, 파일 삭제 같은 위험한 일은 절대 맡길 수 없도록 강력한 차단 규칙과 자동 실패 검사(TC-08)를 만들었습니다.
3. **용량 다이어트 성공**: 안전 조항은 단 하나도 훼손하지 않으면서 중복 표현을 정리해 Antigravity 파일 크기를 **11,534자**로 줄였습니다. (목표치 11,600자 이하 달성, 11,800자 한도 대비 **266자**의 안전 여유 확보)
4. **거짓 없는 투명한 보고**: 아직 실제 수치를 측정하기 전에는 “비용이 절감되었다”고 과장하지 않고 엄격히 UNMEASURED (미측정) 상태로 두었으며, Claude Code가 쉴 때는 정직하게 2도구 검토 상태로 표기했습니다.

### 3.2. 토큰 및 컴퓨팅 예산 거버넌스 8대 핵심 원칙 (outes/token-and-compute-budget.md)
1. **비타협 안전·품질 하한선 (Quality & Safety Floor)**: 비용 절감이나 쿼터 압박을 이유로 보안, 인증, 배포, 파괴적 작업의 기준을 낮출 수 없음 (동급 모델 사용 또는 BLOCKED).
2. **단일 에이전트 기본 (Single-Agent Default)**: 1개 에이전트 작업이 기본이며, 병렬 하위 에이전트는 독립적 실익이 명백할 때만 가동. 최소한의 컨텍스트/도구만 로드.
3. **3회 실패 중단 (Retry Budget)**: 동일 원인 3회 실패 시 무의미한 재시도를 전면 중단하고 근거와 대안 보고.
4. **미래 실행 최저가 배차 (Least-Cost Routing)**: 위험도·범위·가역성을 사전 평가하여 하한선을 만족하는 최저가 모델 선택 (활성 턴 교체 주장 금지).
5. **로컬 엔진(Ollama) 안전 경계**: 저위험, 유계 범위, 비기밀, 로컬 검증 가능 작업에만 허용. 인증·배포·파괴 행위 및 최종 검증 권한 위임 절대 금지.
6. **프롬프트 캐시 안정성 (Prompt Cache Stability)**: 규칙 본문을 안정적으로 유지하여 캐시 무효화에 따른 토큰 낭비 방지.
7. **공급자별 실제 사용량 기록 (Usage Telemetry)**: 실행 시 가용성 확인, 모델·추론강도·사유코드·토큰 사용량 기록.
8. **사전 등록 A/B 실측 전 절감 주장 금지**: A/B 실측 증빙 전까지 모든 수치는 UNMEASURED로 엄격 관리.

### 3.3. 플랫폼별 어댑터 실행 경계 명문화
- **Antigravity** (dapters/antigravity.md): "다음 턴 또는 새 헤드리스 실행에만 적용; 상호작용 가시성이 필요할 때는 IDE, 완전 자동화는 CLI 선택. 활성 턴 전환 주장 금지."
