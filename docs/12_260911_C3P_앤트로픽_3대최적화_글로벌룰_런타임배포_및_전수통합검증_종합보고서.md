## 1. 💡 ELI10 직관 요약 (모르는 걸 모르는 사용자를 위한 쉬운 설명)

### "우리 집 AI 비서 3형제의 뇌(규칙)를 최신 소프트웨어로 완벽히 업그레이드했습니다!"

우리가 스마트폰을 쓸 때, 오래된 앱과 찌꺼기 파일들이 잔뜩 쌓여 있으면 배터리도 빨리 닳고 폰도 버벅거립니다. 이때 공장초기화를 하거나 최신 운영체제(OS)로 깔끔하게 업데이트하면 스마트폰이 날아갈 듯이 빨라집니다.

오늘 우리가 한 일이 바로 이것입니다.
1. **오래된 군더더기 잔소리 청산 (지침 부채 제거)**: 과거 구형 AI에게 하던 불필요한 혼잣말이나 중복 확인 잔소리를 털어내어, 최신 똑똑한 AI가 더 빠르고 정확하게 일하도록 체질을 개선했습니다. (비용 14.6% 절감 효과 입증된 원리 반영)
2. **단골손님 혜택 전면 활성화 (프롬프트 캐싱)**: AI가 매번 똑같은 질문을 처음부터 다시 읽지 않고, 기억해 둔 캐시(KV Cache)를 재사용할 수 있도록 규칙 머리말을 단단하게 고정했습니다.
3. **진짜 성적표 장착 (CPST 복합 지표)**: "토큰을 몇 개 썼는가?"라는 단순한 눈속임 대신, **"작업 1개를 에러 없이 완벽히 끝내는 데 총얼마가 들었는가?"**를 기준으로 삼는 엄격한 규칙 스키마(v1.3.0)를 장착했습니다.
4. **실제 컴퓨터에 즉시 장착 (런타임 배포 완료)**: 설계도만 그린 것이 아니라, 사용자가 작업하는 3대 도구(Antigravity, Codex, Claude Code)의 실제 뇌에 새 규칙을 모두 집어넣었으며, 만약의 사태에 대비해 기존 규칙은 안전한 타임스탬프 백업 폴더에 고이 모셔두었습니다.

## 3. 🛠️ 앤트로픽 3대 낭비 원인과 해결책의 글로벌 룰 전수 구현 내역

### 3.1. 제1기둥: 프롬프트 캐싱 (Prompt Caching)과 접두사 불변성
- **문제점**: 프롬프트 서두에 동적 시간이나 임의 ID를 넣거나 도구 순서를 바꾸면 캐시 적중률이 0%로 추락함.
- **구현**:
  - `core.md`의 P0~P7 헌법을 프롬프트 최상단에 불변 배치.
  - `token-and-compute-budget.md` 제7조: "Preserve prompt and rule stability to reduce unnecessary prompt cache invalidation" 명문화.
  - 도구 스키마 및 규칙 파일의 결정적 정렬(Deterministic Ordering) 준수.

### 3.2. 제2기둥: 지침 부채 (Instruction Debt) 청산과 6대 안티패턴 제거
- **문제점**: 구형 LLM 보완용 중복 검증, 고정 스크래치패드, 장황한 설명 요구가 최신 모델의 내부 CoT 추론을 방해함.
- **구현**:
  - P1: 직설적 능동문 우선, 불필요한 포장 문구 배제.
  - P7: 정적 요약문 제거, 4개 항목(결과/검증/위험/다음) 컴팩트 캡슐화.
  - P4: 텍스트 자가반추 대신 실제 셸에서의 실행 검증(`exit 0`)으로 품질 검증 일원화.

### 3.3. 제3기둥: 노력 수준(Effort Level)과 모델 등급 역전 (Model Inversion) 구조
- **문제점**: 하위 모델에게 긴 생각을 시키면 지연 시간과 비용이 늘어나면서도 오답률이 높음.
- **구현**:
  - `token-and-compute-budget.md` 제5조: 위험도, 모호성, 가역성을 평가하여 "가장 저렴한 적격 모델과 노력 수준"을 결합 배차.
  - 고난도 추론 시 하위 모델의 Max Effort보다 최상위 모델의 Low Effort를 우선 고려하도록 원칙 수립.

### 3.4. 궁극의 평가지표: Cost per Successful Task (CPST)
단위 토큰 단가가 아닌 태스크 1건 성공당 총 투입 비용을 최소화하는 수식을 A/B 검증 스키마에 수용:

$$\text{CPST} = \frac{\sum_{i=1}^{N_{\text{attempts}}} \left( C_{\text{input}}^{(i)} + C_{\text{output}}^{(i)} + C_{\text{thinking}}^{(i)} + C_{\text{tools}}^{(i)} \right)}{N_{\text{success}}}$$
