## 1. 💡 ELI10 직관 요약 (모르는 걸 모르는 사용자를 위한 쉬운 설명)

### "토큰 가격이 싸다고 해서 진짜 비용이 싼 것은 아닙니다"
우리가 택시를 탈 때 100m당 요금이 싼 택시를 탔더라도, 기사님이 길을 헤매서 3번이나 유턴하고 빙빙 돌았다면 결국 요금 폭탄을 맞게 됩니다. 반대로 100m당 요금이 조금 더 비싸더라도 내비게이션을 정확히 보고 한 번에 목적지에 도착한 택시가 최종 요금은 훨씬 적게 나옵니다.

AI 코딩 도구도 똑같습니다.
1. **진짜 비용의 기준 (CPST, 작업당 성공 비용)**: 인공지능에게 말을 거는 글자 수(토큰, Token) 하나의 가격만 따지는 것은 눈속임입니다. "내가 시킨 작업 하나를 에러 없이 완벽하게 끝내는 데 총얼마가 들었는가?"를 따져야 진짜 절약이 됩니다.
2. **단골손님 혜택 챙기기 (프롬프트 캐싱, Prompt Caching)**: 식당에 갈 때마다 내 신분증과 취향을 매번 길게 설명하면 시간과 돈이 듭니다. 한 번 기억해 둔 정보(캐시)를 그대로 재사용하면 요금이 최대 90%까지 대폭 할인됩니다. 단, 메뉴판 앞머리를 매번 바꾸지 않는 안정성(접두사 불변성)이 필요합니다.
3. **오래된 군더더기 규칙 버리기 (지침 부채, Instruction Debt)**: 옛날 똑똑하지 못했던 1~2년 전 인공지능에게 시키던 잔소리("두 번 확인해라", "단계별로 혼잣말을 길게 적어라")를 최신 똑똑한 인공지능에게 그대로 시키면, 혼자서 불필요하게 헛생각을 길게 하느라 돈만 14.6% 더 들고 일도 서툴러집니다. 쓸데없는 군더더기를 털어내는 것이 진짜 기술입니다.
4. **생각의 깊이 조절하기 (Effort Level, 노력 수준)**: 1+1 같은 간단한 덧셈을 시키는데 온 우주의 원리를 깊게 고민하게(Max Effort) 만들면 돈 낭비입니다. 어려운 문제는 깊이 생각하게 하고, 쉬운 문제는 가볍게 답하게 만들어야 합니다. 심지어 가장 똑똑한 모델을 가볍게 생각하게 만드는 것이 어설픈 모델을 끙끙 앓게 만드는 것보다 더 싸고 정확합니다.

### 2.1. 궁극의 평가지표: Cost per Successful Task (CPST)
단위 토큰 단가(예: $3 / 1M 토큰)는 부분 최적화(Local Optimization)의 함정입니다. 태스크의 성공 여부, 재시도 횟수, 추론 토큰량, 도구 호출 횟수를 모두 반영한 전역 최적화(Global Optimization) 지표가 필수적입니다.

$$\text{CPST} = \frac{\sum_{i=1}^{N_{\text{attempts}}} \left( C_{\text{input}}^{(i)} + C_{\text{output}}^{(i)} + C_{\text{thinking}}^{(i)} + C_{\text{tools}}^{(i)} \right)}{N_{\text{success}}}$$

- $C_{\text{input}}$: 기본 입력 토큰 비용 (캐시 미적중 분)
- $C_{\text{output}}$: 생성된 답변 토큰 비용
- $C_{\text{thinking}}$: 확장 추론(Thinking / Reasoning) 토큰 비용
- $C_{\text{tools}}$: 도구 호출(Tool execution roundtrips)에 따른 부가 비용
- $N_{\text{attempts}}$: 3회 실패 제한(Retry Budget) 내 총 시도 횟수
- $N_{\text{success}}$: 검증(exit 0, 테스트 통과, 스키마 일치)을 마친 유효 완료 건수 ($N_{\text{success}} \in \{0, 1\}$)

### 2.2. 제1기둥: 프롬프트 캐싱 (Prompt Caching)과 접두사 불변성 (Prefix Invariance)
- **원리**: 클로드 API의 KV(Key-Value) 캐시는 프롬프트의 처음부터 일치하는 토큰 시퀀스를 재활용합니다.
- **안티패턴**:
  - 프롬프트 서두에 동적 타임스탬프(`2026-09-11 15:30:00`), 세션 고유 UUID, 요청 ID를 삽입하는 행위 -> **캐시 적중률 0%로 추락**.
  - 턴마다 도구(Tool definitions) 정의 순서를 무작위로 변경하거나 중간에 모델을 교체하는 행위.
- **아키텍처 원칙**:
  - **정적 지침(불변 헌법) 최상단 배치**: 시스템 규칙, 안전 하한선, 불변 스키마를 프롬프트 1바이트부터 고정.
  - **도구 정의 순서 정규화(Deterministic Ordering)**: 알파벳순 정렬 고정.
  - **지연 로딩(Lazy Loading)**: 빈도가 낮은 도구는 컨텍스트에 상시 올리지 않고 서브에이전트나 명시적 호출 시에만 주입.

### 2.3. 제2기둥: 지침 부채 (Instruction Debt) 청산과 6대 안티패턴
과거 구형 LLM의 결함을 땜질하기 위해 누적된 중복 지침들이 최신 프론티어 모델의 내부 추론 회로와 충돌하여 불필요한 토큰 낭비와 환각을 유발합니다.
앤트로픽 실측 결과, 6대 안티패턴 제거 시 **비용 14.6% 절감 및 정확도 5.3% 향상**이 입증되었습니다.

| 6대 안티패턴 | 구형 모델 잔재 증상 | 최신 모델 악영향 | C3P 거버넌스 해결책 |
| :--- | :--- | :--- | :--- |
| **① 반복적 중복 검증** | "답변 후 다시 한번 검증하라", "정말 맞는지 재확인하라" | 자기검증 루프에서 무의미한 추론 토큰 과소비 | 런타임 코드 검증(P4 exit 0)으로 일원화, 텍스트 자가반추 축소 |
| **② 과도한 장황 요구** | "아주 상세하게 모든 이유를 서술하라" | 출력 토큰 급증 및 핵심 사실 은폐 | P1 직설적 능동문 우선, P7 컴팩트 캡슐화 |
| **③ 고정 스크래치패드** | `<thinking>`, `<scratchpad>` 블록 강제 | 네이티브 Thinking 토큰과 이중 중복 계산 | 모델 네이티브 추론 기능에 위임, 불필요한 마크다운 태그 강제 철폐 |
| **④ 구형 프롬프트 예시** | 2~3년 전 퓨샷(Few-shot) 예시 방치 | 최신 모델의 내장 지식과 충돌, 문맥 비대화 | 명확한 타입 계약(JSON Schema) 및 최소 대표 예시로 압축 |
| **⑤ 상호 충돌 규칙** | 한쪽에서는 "간결히", 다른 쪽에서는 "완벽히 상술" | 모델의 판단 지연 및 갈지자 행보 | P0 권한 우선순위 명문화로 모호성 제거 |
| **⑥ 맹목적 도구 호출** | 사소한 사실 확인에도 불필요한 도구 연쇄 호출 | 도구 왕복 왕복 지연 및 토큰 폭증 | P4 최소 검증 단위 원칙 및 P5 로컬 읽기 우선 |

### 2.4. 제3기둥: 노력 수준(Effort Level)과 고성능-저추론 역전 구조
- **노력 수준의 비선형 비용**: Low에서 Max로 갈 때 정답률이 19.4%p 향상되지만 비용은 3.5배(350%) 폭증합니다.
- **모델 등급 역전(Model Inversion) 현상**:
  - `하위 모델(Sonnet/Haiku) + High Effort` vs `최상위 모델(Opus) + Low Effort`
  - 복잡한 아키텍처 분석이나 논리적 추론이 요구될 때, 하위 모델에게 긴 생각을 시키는 것보다 최상위 모델에게 간결한 사고를 지시하는 것이 **전체 지연 시간 단축, 토큰 소비 감소, 정답률 상승**을 동시에 달성합니다.
- **CLI 최적화 명령 도입**:
  - `/claude-api hillclimb`: 작업별 최적의 (Model, Effort) 파레토 프론티어 탐색.
  - `/claude-api cost-optimize`: 캐시, 출력 제한, 배치 처리 종합 최적화.

## 4. 🛡️ 비타협 안전 하한선(Safety Floor) 방어 원칙 (REDTEAM 검증)

지침 부채(Instruction Debt) 청산 과정에서 발생할 수 있는 가장 치명적인 위험은 **"비용을 아끼겠다고 필수적인 안전·검증 절차까지 지침 부채로 오인하여 삭제하는 것"**입니다. C3P 협의체는 다음 4대 비타협 영역을 '절대 불변의 안전 헌법'으로 수호합니다.

1. **P2 보안 및 비밀정보 격리 (Non-negotiable)**:
   - `.env`, 개인키, API 토큰의 보호 규칙은 어떠한 경우에도 지침 부채가 아니며 압축·삭제할 수 없습니다.
2. **P4 런타임 무오류 검증 (exit 0)**:
   - "텍스트로 된 자가 반추(Self-reflection)"는 줄이되, 실제 컴퓨터 셸에서 실행되는 테스트, 린트, 빌드 검증(exit 0 확인)은 단 하나도 생략하지 않습니다.
3. **P3/P4 실패 3회 중단 (Circuit Breaker)**:
   - 동일 원인 3회 실패 시 재시도를 중단하는 것은 토큰 낭비를 막는 핵심 방어 기제이므로 영구 유지됩니다.
4. **허위 절감 보고 금지 (UNMEASURED Contract)**:
   - 실제 A/B 실측 텔레메트리 데이터가 수집되기 전까지는 "비용 절감"을 기정사실로 보고하지 않습니다.

## 5. 🗺️ 단계별 추진 로드맵 (Execution Roadmap)

사용자 지침에 따라 3단계를 단번에 처리하지 않고, 한 단계씩 철저한 검증과 브리핑을 거쳐 진행합니다.

```
 [1단계: 완료] ──────────► [2단계: 다음 턴] ──────────► [3단계: 9/12 예약]
 문서 정식 편입              A/B 스키마 보강              Claude Code 쿼터 리셋 연동
 • 앤트로픽 3대 기둥         • pilot_ab_schema.json       • 9월 12일 05:00 KST
 • CPST 수학적 정의          • cost_per_successful_task   • /claude-api prompt-audit
 • C3P 거버넌스 맵핑          • SourceCheck (exit 0) 검증  • C3P 스킬 지침 부채 진단
```

- **1단계 (현재 완료)**: 본 전수분석 보고서(`docs/11_...md`) 발행 및 워크스페이스 편입.
- **2단계 (다음 대화 실행 예정)**: `shared/global-rules/tests/pilot_ab_schema.json` 및 검증 하네스에 `cost_per_successful_task` 메트릭을 정합성 있게 추가하고 `SourceCheck` 무결성 검증.
- **3단계 (9월 12일 05:00 KST 예정)**: Claude Code 주간 쿼터 복귀 즉시 `/claude-api prompt-audit` 도구를 활성화하여 워크스페이스 내 C3P 스킬들의 프롬프트 부채를 정밀 감사.
