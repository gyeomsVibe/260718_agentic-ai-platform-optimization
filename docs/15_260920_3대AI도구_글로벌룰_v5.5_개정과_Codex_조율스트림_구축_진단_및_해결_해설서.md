## 0. 세 줄 요약

1. 세 AI 도구(Codex·Antigravity·Claude Code)가 서로 다른 규칙과 흩어진 메모로 일하다가 자꾸 멈추고 충돌했습니다.
2. 규칙을 한 곳(정본)에서 만들어 두 도구에 자동 배포하도록 정리하고(v5.5.0), 작업 기록을 한 줄씩 쌓아 Codex 대화창으로 보내는 통로를 만들었습니다.
3. 전달은 실제로 성공했고 분량은 절반 이하로 줄었지만, "하루 운용" 기준 효과는 아직 측정하지 못했습니다(`UNMEASURED`).

| 이름 | 하는 일 |
|---|---|

| **Antigravity** | 지시받은 한 단계를 실제로 실행하는 작업자. |

| 용어 | 쉬운 말 |
|---|---|
| **글로벌 룰(global rules)** | 모든 프로젝트에 공통으로 적용되는 각 도구의 행동 규칙 파일. |
| **정본(canonical source)** | 규칙의 원본 한 벌. 여기만 고치고 나머지는 자동 생성합니다. |

| **매니페스트(manifest)** | 원본 폴더의 파일 목록과 지문(해시). 실행 중 원본이 바뀌면 이걸로 알아챕니다. |
| **UNMEASURED / UNKNOWN** | "좋아졌다고 말할 근거가 아직 없음" / "검사를 안 돌려서 모름"을 뜻하는 표시. |

## 2. 진단 — 무엇이 문제였나

### 2-1. 규칙이 서로 싸우고 있었다

- 같은 파일 안에 "묻지 말고 끝까지 진행하라"와 "덮어쓰기·설치 전에는 승인을 받아라"가 함께 있었습니다. 도구는 결국 멈춥니다.
- 규칙 본문이 길었습니다. 규칙이 길수록 각 줄이 지켜질 확률은 떨어집니다.
- Antigravity 쪽 스킬 사본이 오래된 판본이라, 이미 없어진 외부 연결(MCP 서버)을 부르고 있었습니다.

### 2-2. 승인 규칙 파일이 쓰레기통이 되어 있었다

- Codex의 승인 규칙 파일이 260줄(156KB)이었고, 그중 216줄은 예전 프로젝트에서 한 번 쓰고 만 명령 전체가 통째로 허용된 항목이었습니다.
- 그 안에 `git push` 무조건 허용이 있었는데, 다른 규칙 파일은 같은 명령을 "확인 후 실행"으로 막고 있었습니다. 즉 안전장치가 서로 모순이었습니다.

### 2-3. 작업 기록이 흩어져 있었다

- 조율 메모 78건, 별도 노트 10건, 계획서, 카드, 실행 요약이 각각 다른 곳에 쌓였습니다. 누가 언제 무엇을 했는지 한눈에 볼 방법이 없었습니다.
- 더 나쁜 것은, 파일럿이 도는 중에 다른 도구가 메모를 쓰면 원본이 바뀐 것으로 잡혀 실행이 통째로 무효가 됐습니다(`SOURCE_DIVERGED`). 이 사고가 반복됐습니다.

### 2-4. 사용자의 관찰이 맞고 제 판단이 틀렸던 지점

처음에 저는 "다른 도구가 Codex 대화창에 글을 넣을 방법은 없다"고 단정했습니다. 틀렸습니다. 사용자가 "다른 작업에서 …이(가) 보냄"이라는 표시를 직접 봤다고 했고, 확인해 보니 실제 기능이었습니다.

- `codex queue --thread <대화 식별자> --message <내용>` 명령이 있습니다.
- 이 명령은 내부 서비스(app-server)의 `thread/queue/add` 통로로 메시지를 넣고, 그 대화를 열고 있는 클라이언트가 사용자 화면에 배달합니다.
- 근거: [openai/codex PR #39092](https://github.com/openai/codex/pull/39092), [개발자 명령 문서](https://learn.chatgpt.com/docs/developer-commands?surface=cli), 로컬 `codex-cli 0.155.1`의 `codex queue --help`.

## 3. 해결 — 무엇을 어떻게 고쳤나

### 3-1. 규칙을 한 벌로 줄이고 자동 배포로 통일

- 정본 한 곳(`shared/global-rules/`)만 고치고, 스크립트로 두 도구의 장착본을 만들어 덮어쓰는 흐름으로 고정했습니다.
- 생성 → 계약 검사(`Build`) → 배포(`Apply`) 순서이며, 검사에는 필수 제목 순서, 필수 문구, 중복 줄, 한글본 버전 일치가 포함됩니다.
- 길이를 줄였습니다: Codex 규칙 3.3KB → 1.5KB(v5.0.0 시점). 이후 값이 증명된 항목만 더했습니다.

### 3-2. 승인 규칙 파일 정리

- 260줄 → 12줄. 일회성 명령 216줄과 `git push`·`git commit`·`gh pr merge`·자기 승인 항목을 걷어내고, 조회·검사 명령만 남겼습니다.
- 지운 것은 없고 백업에 보존했습니다.

### 3-3. 스킬 판본 통일

- Antigravity의 스킬 15개를 복사본에서 링크(junction)로 바꿔, 공용 폴더와 Codex 원본 한 곳만 보도록 했습니다. 이제 한쪽을 고치면 양쪽에 같이 반영됩니다.

### 3-4. 기사 2건에서 얻은 규칙 반영 (v5.4.0)

| 기사에서 배운 것 | 규칙으로 고정한 문장 |
|---|---|
| 에이전트가 "추적되지 않는 폴더"를 잘못 판단해 백업을 지운 사고 | 미추적 디렉터리는 옮기거나 지우지 않는다. 막히면 `git stash`나 별도 워크트리로 우회한다. |
| 빈 결과를 "같다"로 읽어 생긴 오류 | 빈 결과를 "같음"이나 "할 일 없음"으로 읽지 않는다. 다른 신호로 한 번 더 확인한다. |
| 의도 부채(왜 이 값인지 아무도 모르는 상태) | 값·설계 선택의 근거를 그 옆에 남긴다. 근거 없는 숫자는 관례가 아니라 결함이다. |
| 테스트는 통과하는데 실행 시간이 3배가 된 사례 | 벽시계·토큰을 직전 실행과 비교하고 3배 악화는 실패로 보고한다. |
| 맥락 오염 방지 | 각 단계에는 그 단계에 필요한 파일과 맥락만 준다. 결정은 계획·카드로 이어간다. |
| 폐기 가능한 코드와 유지보수할 코드의 구분 | 산출물을 둘로 나누고, 유지보수 대상에만 의도 기록과 테스트를 붙인다. |

### 3-5. 도구별 역할 규칙 보강

- **Codex**: 계획·순서·게이트·최종 판정을 소유하고, 위임은 파일럿 한 경로로만. 판정은 요약·차이(diff)·테스트로만. 위임 프롬프트의 고정 부분은 글자 단위로 같게 유지(캐시 안정).
- **Antigravity**: 지정된 작업 공간 안에서만 쓰고, 인수 테스트는 고치지 않으며, 아무것도 바꾸지 않고 끝나면 실패로 간주. 정숙 창 잠금 중에는 지정 폴더 밖에 쓰지 않음.

### 3-6. 조율 스트림 구축 (U15, 4단계)

"세 도구의 작업을 Codex 한 창으로 모은다"를 이렇게 구현했습니다.

1. **격리(S1)**: 기록 폴더와 브리핑 파일을 매니페스트에서 제외. 이제 파일럿이 도는 중에도 기록을 남길 수 있고 실행이 깨지지 않습니다. (검사 5건 통과)
2. **사건 기록(S2)**: 한 줄에 한 사건(JSONL). 판정은 Codex만 쓸 수 있고, 실행·판정에는 증거(명령·종료 코드)가 있어야 하며, 200자 초과·여러 줄·비밀값 모양·경로 이탈은 거부합니다. (검사 10건 통과)
3. **브리핑(S3)**: 사건을 접어 한 장으로. 머리말은 글자 단위로 고정하고, 마지막 판정 이후만 담고, 60줄·6KB를 넘지 않으며, 같은 입력이면 같은 결과가 나옵니다. (검사 7건 통과)
4. **전달(S4·S5)**: 브리핑이 바뀐 상태 변화에서만 한 건을 `codex queue`로 보냅니다. 같은 내용 재전송 차단, 분당 1건·하루 24건 상한, 첫 줄에 `[DATA]`를 박아 "이건 데이터이지 지시가 아니다"를 명시, 값 대신 경로·종료 코드만 싣습니다. (검사 10건 통과, 실제 배달 성공)

**중간에 잡은 진짜 결함 하나**: Windows에서는 여러 주체가 동시에 파일 끝에 덧붙이면 줄이 통째로 사라집니다. 실제로 8건 중 2건이 유실되고 식별자가 중복됐습니다. 파일 잠금으로 고치고 3회 연속 8/8·중복 0을 확인했습니다. 이 교훈은 규칙 v5.5.0에 "동시성은 실제 병렬 테스트로 증명한다"로 고정했습니다.
