# 빠른 실행·예산 계약

## 기본 전략

`compile first, expand on evidence`를 적용하세요. 성공에 필요한 최소 후보를 먼저 만들고, 실제 실패·중대한 불확실성·사용자 요청이 있을 때만 조사와 산출물을 확장하세요.

## 세 속도 라우터

| 경로 | 사용 조건 | 산출물 |
|---|---|---|
| `FAST` | 기본값, 핵심 작업과 안전 경계가 명확함 | 권장안 1개, 최소 후보, 가장 싼 유효 검사 |
| `STANDARD` | 한 가지 중요한 불확실성이나 실패 원인이 있음 | 필요한 조사만 추가한 수정 후보와 비교 결과 |
| `DEEP` | 사용자가 심화를 요청하거나 실패 비용·충돌·복잡도가 큼 | `/DEEPDIVE + /ALT3 + /EXPERT`, 전체 PRD, 강화 평가 |

가장 낮은 경로에서 시작하세요. 상위 경로로 올라가는 이유와 바뀔 결정을 한 문장으로 설명할 수 없으면 올라가지 마세요.

## FAST 기본 예산

- 질문: 기본 0개, 진행을 막는 질문 최대 1개
- 설계안: 권장안 1개
- 외부 근거: 캐시 우선, 기본 3개 출처 계열 이내
- 비교 대상: 가장 가까운 대안 1개와 무-Skill 기준선
- 후보: 핵심 작업 하나를 수행하는 최소 파일 구성 1개
- 품질 수정: 중대한 결함에 대한 집중 반복 1회
- 검증: 다음 성숙도에 필요한 가장 싼 검사부터 1단계씩
- 유료 호출과 외부 상태 변경: 기본 0회, 실행 직전 별도 승인

숫자는 품질이나 안전을 희생하는 절대 한도가 아니라 비용 경보입니다. 한도를 넘기기 전에 추가 작업이 어떤 결정을 바꾸는지 확인하세요. 바뀌는 결정이 없으면 중단하세요.

## 절대 품질 하한선

속도와 관계없이 다음 다섯 항목은 생략하지 마세요.

1. 핵심 작업 하나와 비목표
2. 사용자 출력 형식 또는 제공된 Few-Shot 계약
3. 가장 가까운 대안 또는 무-Skill 기준선
4. 가장 치명적인 실패·오용 경로와 최소 통제
5. 현재 성숙도에 맞는 가장 싼 정적 검사

하한선 중 하나라도 실패하면 설치나 외부 실행으로 넘어가지 마세요.

## 확장 조건

다음 중 하나일 때만 `STANDARD` 또는 `DEEP`으로 확장하세요.

- 사용자가 `/DEEPDIVE`, `/ALT3`, 전체 PRD 또는 다중 플랫폼 검증을 명시 요청함
- 보안·법률·금전·개인정보처럼 실패 비용이 큼
- 최신 플랫폼 계약이나 라이선스를 확인하지 않으면 실행할 수 없음
- 빠른 후보가 사전 성공 기준에 실패했고 원인 확인에 추가 근거가 필요함
- 두 근거가 실제로 충돌하며 선택에 영향을 줌

확장 전에 예상 추가 작업, 비용을 만드는 요인, 기대하는 결정 변화를 한두 문장으로 알리세요. 유료 서비스, 패키지 설치 또는 외부 상태 변경은 별도 승인을 받으세요.

## 정보가치 예산 규칙

추가 질문·검색·문서·반복마다 다음 순서로 판단하세요.

1. 이 작업이 바꿀 구체적인 결정은 무엇인가?
2. 그 결정이 품질·안전·비용에 미치는 영향이 큰가?
3. 더 싼 방법으로 같은 불확실성을 줄일 수 있는가?
4. 예상 이득이 시간·토큰·유료 비용보다 큰가?

첫 질문에 답할 수 없거나 예상 이득이 비용보다 작으면 중단하세요. 비용을 정확히 계산할 수 없으면 `낮음`, `중간`, `높음`으로 표시하고 안전한 작은 범위를 선택하세요.

## 지름길 선택 순서

1. 기존 Skill 그대로 재사용
2. 기존 Skill의 작은 수정
3. 검증된 템플릿으로 최소 후보 생성
4. 제한된 추가 조사 후 후보 생성
5. 심층 조사와 전체 PRD

위쪽 선택지가 성공 기준을 만족하면 아래쪽으로 내려가지 마세요.

## 비용 누수 차단

- 이미 확인한 질문, 검색과 검사를 반복하지 마세요.
- 같은 내용을 PRD, 보고서, JSON과 본문에 중복 작성하지 마세요.
- 출처 수를 품질로 간주하지 말고 의사결정에 기여한 근거만 남기세요.
- 모든 플랫폼을 미리 검증하지 말고 사용자가 실제 사용할 플랫폼부터 검증하세요.
- 정적 검사 실패 상태에서 런타임·외부 실행 비용을 쓰지 마세요.
- 차별점이나 측정 가능한 이득이 없으면 새 Skill 생성을 중단하고 기존 대안을 권고하세요.
- 추가 반복의 예상 개선이 작거나 측정 불가능하면 현재 최선안을 인계하세요.

## 완료 기준

완벽함이 아니라 사용 가능한 다음 결과를 기준으로 완료하세요. `무엇이 완성됐는지`, `어떤 최소 검사에 통과했는지`, `다음 투자가 필요한 조건`만 짧게 보고하세요.

기본 보고 형식을 고정하세요.

```text
결과: <완성된 후보 또는 권고>
근거: <결정을 지지한 핵심 근거 1~3개>
검사: <실행 결과와 성숙도>
주의: <남은 중대한 위험 또는 없음>
다음: <필요한 가장 작은 승인 또는 종료>
```

사용자가 전체 PRD, 근거 원장 또는 단계별 설명을 요청한 경우에만 상세 부록을 펼치세요.
