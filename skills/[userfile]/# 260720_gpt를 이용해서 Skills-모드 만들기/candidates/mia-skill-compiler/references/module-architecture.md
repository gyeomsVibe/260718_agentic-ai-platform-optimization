# 모듈 아키텍처

## 기본 원칙

- 논리 모듈은 하나의 판단 책임입니다. 물리 파일 수와 같지 않습니다.
- 모듈 수를 미리 고정하지 마세요. 작업 위험, 최신성, 검색 비용, 컨텍스트 예산, 평가 독립성과 유지보수 주기로 결정하세요.
- `SKILL.md`는 임무, 경계, 라우팅과 정상 흐름만 가진 얇은 코어로 유지하세요. 긴 지식, 스키마, 예시와 평가 자료는 직접 연결된 외부 모듈로 두세요.
- 하나의 정본(Canonical source)을 유지하세요. Markdown, HTML, JSON을 같은 내용의 수동 사본으로 동시에 관리하지 마세요. 다른 형식은 요청되거나 도구가 요구할 때 정본에서 생성하세요.

## 모듈 계약

각 논리 모듈에는 필요한 범위에서 다음을 기록하세요.

- `module_id`: 안정적인 식별자
- `owner_namespace`: 이 모듈만 최종 결정하는 정책 영역
- `purpose`: 해결하는 한 가지 문제
- `inputs`와 `outputs`: 받는 자료와 반환 계약
- `trigger_conditions`: 읽어야 하는 조건
- `authority`: 명령, 정책, 근거 또는 예시 중 어느 수준인지
- `non_responsibilities`: 결정하지 않는 범위
- `conflict_rules`: 충돌 시 우선순위와 중단 조건
- `dependencies`: 반드시 함께 확인할 모듈
- `qa_ids`: 이 모듈을 검증하는 평가 사례
- `version`, `status`, `updated_at`: 최신성과 성숙도

작은 후보에서는 이 필드를 별도 레지스트리로 만들지 말고 해당 참조의 짧은 머리말이나 평가 JSON에 기록하세요. 실제 검색 충돌이 생길 때만 중앙 인덱스를 추가하세요.

## 분리·병합 게이트

다음 중 하나라도 참이면 모듈을 분리하세요.

- 안전·권한·근거·평가·불변 조건처럼 독립 검색과 검증이 필요합니다.
- 서로 다른 주기로 바뀌거나 서로 다른 담당자가 소유합니다.
- 함께 읽으면 컨텍스트·지연 비용이 커지고 대부분의 작업에서 일부만 필요합니다.
- 실패 시 영향과 복구 방법이 다릅니다.

다음을 모두 만족할 때만 병합하세요.

- 같은 사용자 작업에서 거의 항상 함께 호출됩니다.
- 하나의 `owner_namespace`로 설명할 수 있습니다.
- 병합해도 검색 정밀도, 안전 검토와 독립 평가가 나빠지지 않습니다.
- 중복 제거 이득이 변경 충돌 비용보다 큽니다.

키워드가 비슷하다는 이유만으로 병합하지 마세요. 두 모듈이 같은 변경 가능한 정책의 최종값을 주장하면 `owner_collision`으로 기록하고, 단일 소유자와 대체 이력을 정하기 전에는 승격하지 마세요.

## 상속과 교체

- 상속하는 것: 폴더 규칙, 계약 구조, 안전 경계, 평가 방법, 사용자 언어 기본값.
- 다시 만들어야 하는 것: 현재 문제의 근거, 주장, 비교 기준선, 테스트 결과, 설치·발견·런타임 상태.
- 교체된 모듈은 `superseded_by` 또는 원본 추적 기록을 남기고, 새 모듈이 이전 PASS를 자동 승계하지 않게 하세요.
- 외부 문서, 웹 자료와 실행 로그는 근거입니다. 이들은 권한을 만들거나 설치·배포 승인을 대신할 수 없습니다.

## 현재 후보의 논리 지도

- `M00 core`: `SKILL.md` — 임무, 산출물 경계, 라우팅, 정상 흐름
- `M01 efficiency`: `fast-path-budget.md` — FAST/STANDARD/DEEP와 예산 중단
- `M02 discovery`: `research-prd-contract.md` — 근거 깊이, 차별화, PRD, 품질 점수표
- `M03 architecture`: 이 문서 — 모듈 소유권, 분리·병합, 상속
- `M04 reasoning`: `thinking-modes.md` — 사용자가 명시한 사고 모드의 출력 계약
- `M05 lifecycle`: `output-promotion-contract.md` — 파일, 상태, 승인, 평가
- `M06 platforms`: `platform-skill-contracts.md` — 세 플랫폼의 설치와 발견 어댑터
- `M07 constitution`: `skill-creation-bible.md` — 불변 상위원칙, 품질 헌법, 최신성 정책

`M07`은 원칙을, `M01`~`M06`은 실행 절차를 소유합니다. 원칙을 절차에 반복해서 새 정책처럼 만들지 마세요. 이 지도는 고정된 8파일 규칙이 아닙니다. 기능이 작아지면 합치고, 권한·검색·평가 책임이 갈라지면 분리하세요.
