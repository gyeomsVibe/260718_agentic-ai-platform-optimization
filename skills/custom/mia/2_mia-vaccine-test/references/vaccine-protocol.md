# MIA 백신 테스트 프로토콜 (핵심 요약)

> SKILL.md의 압축 참조. 교본 전체는 vibe-clinic 저장소 `handbook/` 06~08장.

## 세 모드

| 모드 | 심는 것 | 답하는 질문 |
|---|---|---|
| A 실패주입 | 실패 **상태** | 실패했을 때 화면·흐름이 버티나? |
| B 변이테스트 | 코드 **버그** | 우리 테스트가 진짜 결함을 잡나? |
| C 실사용진단 | 없음(실사용) | 실제로 전 기능이 작동하나? |

## 공통 5단계

1. **격리** — 복제본·임시 폴더에서만
2. **기록** — 주입 전 정상 상태를 화면 기준으로
3. **주입** — 한 번에 하나만, 적용됐는지 먼저 확인
4. **관찰** — 화면을 직접 본다 (로그·200 응답으로 판단 금지)
5. **항체** — 원인 수정 + 재발 방지 검사 + "왜 못 잡았나" 기록

## 절대 규칙

- 검사·진단을 약화시켜 통과시키지 않는다
- 주입한 것은 전부 원복하고 확인한다
- 실행하지 않은 검증을 했다고 말하지 않는다
- 주입이 안 먹혔는데 화면이 멀쩡한 것을 "문제없음"으로 결론내지 않는다

## 변이 점수 기준 (모드 B)

- 75~85% 견실, 90%+ 우수, 핵심 경로(결제·인증·안전)는 더 높게
- **100%를 좇지 말 것.** 점수보다 살아남은 변이 개별 판단이 중요
- 살아남았어도 피해가 없으면(동등 변이·죽은 코드) 테스트를 만들지 않고 기록

## 실행 환각 대응 (모드 C — 핵심)

에이전트가 **수행하지 않은 단계를 완료했다고 주장**할 수 있다(Execution Hallucination).
UI에서는 "존재하지 않는 버튼을 눌렀다"로 나타난다. 대응은 **행동 전후 상태 관측**:

| 증거 | 내용 |
|---|---|
| 한 일 | 어떤 요소를 어떻게 조작 |
| 전 | 조작 직전 관측값 |
| 후 | 조작 직후 관측값 — 전과 달라야 실제 실행 |

**전 = 후면 작동한 게 아니다.** 확인 못 한 항목은 `⛔미검증`으로 분리.

## 항체 = vibe-clinic 연계

확정된 결함 하나 = 진단 파일 하나(`.vibe-clinic/diagnostics/<id>.clinic.js`).
백신 테스트는 찾고, vibe-clinic은 기억하고 매번 재검사한다.
항체는 **고치기 전 코드에서 실제로 실패**(빨간불)해야 진짜다. 다른 언어는 브리지로 연결(pytest 등).
