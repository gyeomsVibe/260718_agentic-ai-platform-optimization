# 산출물·승격 계약

## 파일 배치

실행 후보에는 `SKILL.md`, 필요한 `agents/openai.yaml`, 직접 연결된 `references/`, 결정적 `scripts/`만 두세요. 원본 추적, 조사 원장, 평가 사례, 결과와 벤치마크는 후보 밖의 `fixtures/<name>/`와 `evals/<name>/`에 두세요.

## 평가 순서

1. 이름, 프런트매터, 링크, 민감 파일명과 위험 명령을 정적으로 검사하세요.
2. 새 작업 또는 재시작된 작업 공간에서 보이는 Skill 이름과 시간을 기록하여 `DISCOVERY_CONFIRMED`를 확인하세요.
3. 명시 호출, 비발동, 불완전 입력, 핵심 작업과 안전 거부 사례를 실행하세요.
4. 같은 사례를 무-Skill 기준선과 가장 가까운 대안에 실행하세요.
5. 성공률, 트리거 오류, 안전 실패, 시간·토큰 비용과 플랫폼 드리프트를 비교하세요.

파일 복사나 해시 일치는 설치 무결성만 증명합니다. 발견이나 작업 성공을 증명하지 않습니다.

정적 구조 통과, 설치 무결성, 플랫폼별 발견, 명시 호출, 핵심 작업, 안전 사례, 기준선 비교와 교차 플랫폼 결과를 하나의 PASS로 합치지 마세요. 이전 후보나 다른 플랫폼의 상태도 상속하지 마세요.

## 읽기 전용 설치 사전검사

설치 계획을 만들기 전에 `scripts/preflight_skill_promotion.py`를 실행하세요. 후보에 포함된 다른 스크립트는 실행하지 마세요.

사전검사는 다음을 확인합니다.

- `SKILL.md`와 폴더 이름 일치
- 허용된 최상위 구조와 민감 파일명
- 심볼릭 링크, 후보 밖 링크와 위험 명령
- 파일별 SHA-256 목록
- 정규화한 대상 경로가 허용 루트 안인지 여부
- 기존 대상 충돌과 원본·대상 동일 경로

대상을 지정할 때 `--allowed-target-root`를 생략하지 마세요. 기본 `--target-state absent`는 기존 대상이 있으면 실패합니다. 사전검사 통과는 설치 계획을 검토할 수 있다는 뜻일 뿐 설치 승인이나 설치 안전 전체를 증명하지 않습니다.

## 승인 카드

외부 상태를 바꾸기 직전에 다음을 한국어로 보여주세요.

- 수행할 한 가지 작업
- 정확한 대상과 변경 범위
- 필요한 이유와 예상 효과
- 주요 위험과 실행하지 않을 항목
- 실패 시 복구 방법
- 승인하지 않을 때 보존되는 결과

프로젝트 설치와 전역 설치, 기존 대상 덮어쓰기, 후보 스크립트 실행, 외부 API, 게시·배포·커밋·푸시는 서로 독립적인 승인으로 취급하세요. 기본값은 미리보기와 dry-run입니다.

승인되면 미리 보여준 대상과 작업만 수행하세요. 설치 후 파일별 무결성을 확인하고, 새 작업에서 `DISCOVERY_CONFIRMED`가 기록되기 전에는 호출·작업·플랫폼 성공 사례를 실행하거나 성공으로 기록하지 마세요. 외부 실행은 승인된 도구·입력·횟수·대상 범위를 벗어나지 마세요.

대상이 이미 있으면 기본적으로 중단하세요. 덮어쓰기는 변경 목록, 별도 백업 위치, 복구 방법과 별도 승인을 모두 확보한 경우에만 진행하세요. 원본과 설치본의 상대 경로 집합과 파일별 SHA-256이 다르면 발견 평가로 넘어가지 마세요.

세 플랫폼 평가에서는 [플랫폼 Agent Skill 계약](platform-skill-contracts.md)을 적용하고 플랫폼별 결과를 따로 기록하세요. 어느 플랫폼에서도 GPT Builder용 패키지를 대신 생성하지 마세요.

## 호환성 전환

`mia-skill-forge`의 기존 후보와 평가 기록은 과거 근거로 보존하세요. 새 작업과 새 평가에는 `mia-skill-compiler`를 사용하세요. 이전 이름의 설치본을 자동 삭제하거나 덮어쓰지 말고, 발견 확인 후 별도의 제거 승인을 받으세요.
