# Skill 사용 매뉴얼

> **스킬이 뭔지 몰라도 됩니다.** 이 문서는 그 상태에서 시작해도 읽힙니다.
> 외울 필요도 없습니다. 필요할 때 **2장에서 상황을 찾아 문구를 복사**하면 됩니다.
>
> 기준 시점: **2026-09-05** · 기존 스킬과 새 슬래시 모드의 검증 수준을 구분해 기록합니다.

## 1. 30초 요약

**AI에게 "이런 일은 이런 순서로 해라"를 미리 가르쳐 둔 것**이 스킬입니다.

없으면 AI가 그때그때 다르게 일합니다. 있으면 정해진 절차와 점검 항목을 따릅니다.
**결과가 들쭉날쭉하지 않게 되는 것**이 핵심 이득입니다.

지금 쓸 수 있는 것에는 일반 자연어로 찾는 Skill과 `/`로 직접 부르는 명령 모드가 있습니다.

| 도구 | 스킬 | 서브에이전트 |
|---|---|---|
| **Claude Code** | 기존 12개 + 슬래시 본체·별칭 11개 | 4개 |
| **Codex** | 기존 16개 + 슬래시 본체·별칭 11개 | — |
| **Antigravity** | 기존 15개 + 슬래시 본체·별칭 11개 | — |

**세 가지만 기억하면 충분합니다.**

1. 그냥 평소처럼 말하면 AI가 알아서 꺼내 씁니다
2. 안 걸리면 **스킬 이름을 그대로 말하세요** — 이게 가장 확실합니다
3. **막히면 `원터치 점검해줘`** — 뭘 해야 할지 모를 때의 만능 입구입니다

### 짧은 `/명령`으로 답변 방식을 바꾸기

이번 독립 Skill은 자동 선택을 노리지 않습니다. 할 일과 함께 `/`가 붙은 모드를 직접 적습니다.

```text
/CRITIC /OPTIMIZE 이 기획서의 치명적 약점을 찾고 최소 수정안으로 고쳐줘
```

| 목적 | 명령 |
|---|---|
| 다시 검토·수정 | `/SELFREFINE` |
| 적대적 실패 찾기 | `/REDTEAM` |
| 쉽게 설명 | `/ELI10` |
| 근거까지 깊게 조사 | `/DEEPDIVE` |
| 다른 대안 3개 | `/ALT3` |
| 결함 비평 | `/CRITIC` |
| 기준 대비 최적화 | `/OPTIMIZE` |
| 따라 할 절차 | `/STEPBYSTEP` |
| 전문 기준 적용 | `/EXPERT` |
| 예시 구조 고정 | `/STRUCTURED FEW-SHOT` |

대문자와 소문자(`/OPTIMIZE`, `/optimize`) 양 끝 표기를 지원하도록 설계했지만, 임의 혼합
대소문자는 세 도구 공통 보장이 아닙니다. Codex·Claude Code의 과거 단발 응답은 통과했지만
별칭 본문 의미 결함이 뒤늦게 확인되어 교정본을 세 도구에 재배포했으며 전수 재평가는 필요합니다. Antigravity는
구조·해시만 확인되어 새 IDE 세션 발동 검증도 남았습니다.
자세한 조합과 한계는 [Slash Prompt Modes README](custom/slash-prompt-modes/README.md)를 보세요.

## 2. 이럴 때 이렇게 말하세요 (복사해서 쓰세요)

찾는 순서를 뒤집었습니다. **"무슨 스킬이 있지?"가 아니라 "지금 내 상황이 뭐지?"** 로 찾으세요.

### 🔧 뭔가 잘못됐을 때

| 내 상황 | 이렇게 말하세요 | 뜨는 스킬 |
|---|---|---|
| 프로젝트가 뭔가 이상한데 뭐가 문제인지 모르겠다 | `원터치 점검해줘` | `vibe-check` |
| 버그가 났는데 원인을 못 찾겠다 | `이 버그 원인부터 찾아줘` | `systematic-debugging` |
| 테스트가 깨졌다 | `테스트가 실패하는데 왜 그런지 봐줘` | `systematic-debugging` |
| 에러 났을 때 사용자가 뭘 보는지 걱정된다 | `에러 경로 분석해줘` | `error-path-analysis` |
| 화면이 비었을 때 처리를 안 해둔 것 같다 | `빈 상태 점검해줘` | `error-path-analysis` |

> **`원터치 점검해줘`가 가장 쓸모 있습니다.** 진단 → 최소 수정 → 재진단 → 보고까지
> 알아서 합니다. 당신은 큰 승인만 하면 됩니다.

### ✍️ 글·문서를 쓸 때

| 내 상황 | 이렇게 말하세요 | 뜨는 스킬 |
|---|---|---|
| 문서를 썼는데 잘 썼는지 모르겠다 | `내 문서 리뷰해줘` | `writing-guidelines` |
| 문체가 들쭉날쭉한 것 같다 | `글 스타일 점검해줘` | `writing-guidelines` |
| README·API 문서·체인지로그가 필요하다 | `README 작성해줘` | `technical-writer` (에이전트) |

### 🎨 화면을 만들 때

| 내 상황 | 이렇게 말하세요 | 뜨는 스킬 |
|---|---|---|
| 화면을 새로 만들고 싶다 | `UI 만들어줘` · `랜딩 페이지 만들어줘` | `frontend-design-specialist` (에이전트) |
| 만든 화면이 규칙을 지켰는지 보고 싶다 | `접근성 검사해줘` · `UI 검증해줘` | `web-design-guidelines` |

> 두 개는 **역할이 다릅니다.** 앞은 *만드는* 쪽, 뒤는 *검사하는* 쪽입니다.
> 만들고 나서 검사하면 됩니다.

### 🐍 코드를 다룰 때

| 내 상황 | 이렇게 말하세요 | 뜨는 스킬 |
|---|---|---|
| 파이썬 코드가 지저분하다 | `이 파이썬 코드 리팩토링해줘` | `python-refactor` |
| 타입·설명을 붙이고 싶다 | `타입 힌트 추가해줘` | `python-refactor` |
| 테스트를 만들고 싶다 | `테스트 작성해줘` · `TDD로 구현해줘` | `test-writer` (에이전트) |
| API를 설계해야 한다 | `API 설계해줘` · `엔드포인트 추가해줘` | `api-architect` (에이전트) |
| 코드 리뷰를 받았는데 어떻게 반영할지 모르겠다 | `이 리뷰 피드백 어떻게 반영할지 봐줘` | `receiving-code-review` |

> `receiving-code-review`는 **받은 지적을 그대로 따르지 않고 먼저 검증**하게 합니다.
> 틀린 지적을 무비판적으로 반영하는 사고를 막습니다.

### 💡 뭘 만들지 정할 때

| 내 상황 | 이렇게 말하세요 | 뜨는 스킬 |
|---|---|---|
| 아이디어는 있는데 정리가 안 된다 | `컨셉 잡아줘` · `이 아이디어 어때` | `product-thinking` |
| 경쟁 상황을 보고 싶다 | `경쟁 분석해줘` | `product-thinking` |
| 큰 결정을 근거 있게 내리고 싶다 | `MIA 전략스킬 발동` | `mia-strategic` |

### 🛡️ 위험한 순간 — 당신이 부르지 않아도 됩니다

**`accidental-data-loss-prevention`은 스스로 끼어듭니다.**

DB 테이블 삭제, 클라우드 파일 삭제처럼 **되돌릴 수 없는 작업** 앞에서 AI를 멈춰 세우고,
무슨 일이 벌어지는지 설명한 뒤 당신의 승인을 요구합니다. 부르는 스킬이 아니라 **안전벨트**입니다.

실제로 확인했습니다. `users 테이블을 DROP 해줘`라고 했더니 멈춰 서서 다른 테이블이
그 테이블을 참조한다는 것까지 짚어 주고 승인을 요청했습니다.

## 3. 개념 — 궁금할 때만 읽으세요

2장만으로 충분합니다. 여기는 **왜 그렇게 되는지** 알고 싶을 때 보세요.

### 스킬은 레시피 카드입니다

요리사에게 "김치찌개 해줘"라고만 하면 자기 방식대로 만듭니다. 레시피 카드를 미리 줘 두면
**매번 같은 순서와 기준으로** 만듭니다. 스킬이 그 카드입니다.

### AI는 어떻게 고르나

대화가 시작될 때 AI는 설치된 스킬들의 **이름과 한 줄 설명만** 미리 읽어 둡니다.
당신 요청이 어떤 설명과 맞아떨어지면, 그때 **그 스킬 본문을 펼쳐 읽고** 그대로 일합니다.

여기서 두 가지가 따라옵니다.

- **많다고 좋은 게 아닙니다.** 설명 목록이 길어지면 엉뚱한 스킬이 튀어나옵니다.
  그래서 127개였던 것을 **43개로 줄였습니다**([DEPLOYMENT.md](DEPLOYMENT.md)).
- **말하는 방식이 영향을 줍니다.** 그래서 2장에 실제 문구를 그대로 적어 뒀습니다.

### 서브에이전트는 뭐가 다른가

| | 스킬 | 서브에이전트 |
|---|---|---|
| 누가 일하나 | 지금 대화 중인 AI | **새로 뜬 별도 AI** |
| 대화 기록 | 이어짐 | **백지에서 시작** |
| 좋은 점 | 맥락 유지, 빠름 | 긴 작업 격리 |

**Claude Code에만 있고, 보통 AI가 알아서 부릅니다.** 이름을 외울 필요 없습니다.

### 왜 도구마다 다른가

세 도구가 **서로 다른 폴더**를 읽습니다. 공용 폴더는 **없습니다.**

| 도구 | 읽는 폴더 |
|---|---|
| Claude Code | `~/.claude/skills` |
| Codex | `~/.codex/skills` + `~/.agents/skills` |
| Antigravity | `~/.gemini/config/skills` 계열 |

**한 도구에서 됐다고 다른 도구도 되리라 넘겨짚지 마세요.** 실제로 오래 잘못 알고 있었습니다.

## 5. MIA 시리즈 — 부르는 방법이 엄격합니다

윤겸스가 직접 만든 셋입니다. **`MIA` + 붙여쓴 이름 + `발동`/`해줘`** 형식을 지켜야 합니다.

| 스킬 | 무엇을 하나 | 발동 문구 |
|---|---|---|
| `mia-strategic` | 큰 결정을 기획→검토→실행→검증 4단계로 | `MIA 전략스킬 발동` |
| `mia-skill-compiler` | 새 스킬을 만들거나 기존 스킬 개선 | `MIA 스킬컴파일러 발동` |
| `mia-vaccine-test` | 일부러 고장 내서 숨은 결함 찾기 | `MIA 백신테스트 발동` |

```
❌ 백신 테스트 해줘      (접두사 없음 + 띄어씀 → 발동 안 하는 게 정상)
✅ MIA 백신테스트 발동
```

**왜 이렇게 까다롭게 만들었나**: `mia-vaccine-test`는 코드를 **일부러 파괴**합니다.
아무 때나 튀어나오면 위험해서 일부러 좁혔습니다.

> 2026-08-05에 이 방어가 뚫려 있던 것을 발견해 고쳤습니다. `백신 테스트 해줘`만 해도
> 발동했었습니다. 지금은 막혔고, 정상 문구는 그대로 동작하는 것까지 확인했습니다.

## 6. 안 될 때 — 순서대로

### ① 새 대화를 여세요

**스킬 목록은 대화가 시작될 때 한 번 읽힙니다.** 방금 설치했다면 지금 대화에서는
안 보일 수 있습니다.

### ② 이름을 직접 부르세요 ← 가장 확실합니다

돌려 말하면 안 걸릴 수 있습니다. **스킬 이름을 그대로 말하는 게 100%에 가깝습니다.**

```
web-design-guidelines 스킬 써서 이 화면 점검해줘
```

**외울 필요 없습니다.** 2장 표에서 이름을 복사하세요.

### ③ 도구를 확인하세요

Codex에만 있는 걸 Claude Code에서 부르고 있는지 보세요. 3장 표를 참조하세요.

### ④ 직접 확인하는 명령

```bash
claude -p "vibe-check 스킬이 목록에 있는지 있음/없음으로만 답하세요." --permission-mode plan
```

목록 전체를 나열시키면 AI가 몇 개 빠뜨릴 수 있습니다. **이름을 지목해서** 물으세요.

### ⑤ 파일이 깨졌는지 검사

저장소 루트에서 실행하면 도구 폴더 전체를 규격 검사합니다.

```bash
npm run skills:audit
```

`오류 0건`이 정상입니다.
